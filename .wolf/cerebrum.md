## User Preferences

- Wants **reversible destructive/state-changing actions**. When proposing a flow that moves or removes something, always include an undo affordance — the user explicitly asked for an undo button on shopping-list check-off "in case the user accidentally checks off something they didn't mean to."
- Prioritizes **seamless UX and simplicity** over feature richness. The app "should ultimately help users with one thing — reduce waste." Prefer fewer taps and fewer screens; resist adding features.
- Prefers **warnings over hard blocks**. Duplicate-add should inform, not prevent — the user may legitimately need a second broccoli.
- Chose whole-number quantities over count+unit, and deferred expiry/freshness out of v1 — consistently picks the simpler option when offered.

## Key Learnings

- **Project:** nomorewaste — an iOS SwiftUI grocery list that doubles as a home inventory, so users can see what they already own before buying more.
- **Xcode project uses `PBXFileSystemSynchronizedRootGroup`** (Xcode 16+). New `.swift` files dropped into `nomorewaste/` join the target automatically — do NOT edit `project.pbxproj` to add source files. Adding a new *target* (e.g. unit tests) still requires project edits.
- **Deployment target was iOS 27.0, being lowered to 18.0.** 27.0 would restrict installs to devices on the newest OS for no benefit; the CloudKit sharing APIs go back to iOS 15/16.
- **CloudKit requires a PAID Apple Developer Program membership.** Free personal-team provisioning cannot grant the iCloud entitlement — on device *or* in the simulator. The user's membership was **approved 2026-07-21** (purchased the same day), so nothing in this project is account-blocked. The former phase-1/phase-2 split in `tasks.md` is gone.
- **`PRODUCT_BUNDLE_IDENTIFIER` is still the Xcode placeholder** (`devplaceholder.$(PROJECT_UNIQUE_VALUE:identifier).$(PRODUCT_NAME:rfc1034identifier)`). It must be replaced with a real reverse-DNS ID *before* creating the CloudKit container — the container is bound to the App ID, and changing the bundle ID afterwards orphans it.
- **There is no Info.plist file.** The target uses `GENERATE_INFOPLIST_FILE = YES`, so plist keys (`CKSharingSupported`, etc.) are set as `INFOPLIST_KEY_<key>` build settings. There is also no `CODE_SIGN_ENTITLEMENTS` yet — adding the iCloud capability creates the entitlements file.
- **CloudKit's development environment is resettable; production is append-only.** Iterating on the model with sync on is safe until the first TestFlight push. That is what makes "sync on from the start" cheap.
- **Enable `NSPersistentHistoryTrackingKey` from the first release**, even before sync is on — retrofitting history tracking after data exists is painful.
- **CloudKit model constraints (get these right up front):** every attribute optional or defaulted, no unique constraints, every relationship needs an inverse.
- **Testing sharing needs two iCloud accounts and realistically two physical devices** — simulator-to-simulator share acceptance is unreliable.
- **SwiftUI has no native hook for CloudKit share acceptance** — a minimal `UIApplicationDelegateAdaptor` implementing `application(_:userDidAcceptCloudKitShareWith:)` is unavoidable. Sending side can use `ShareLink` + `CKShareTransferRepresentation` instead of `UICloudSharingController`.
- **`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`** and `SWIFT_APPROACHABLE_CONCURRENCY = YES` are set project-wide. Types are main-actor-isolated by default; UI and model code needs no explicit concurrency annotations.
- **No test target exists.** Verification currently relies on `#Playground` blocks (the app template already imports `Playgrounds`) and manual simulator runs. Keep pure logic free of SwiftUI/SwiftData deps so it stays playground- and future-test-friendly.
- `SUPPORTED_PLATFORMS` includes macosx and xros, but the design targets iPhone interaction patterns.
- **`.wolf/anatomy.md` is regenerated by the OpenWolf scanner, not hand-maintained.** It re-sorts entries alphabetically and strips any prose that is not a `- \`file\` — description` bullet. Per-file descriptions you write DO persist across rescans; intro paragraphs and section notes do not. Put durable guidance in `CLAUDE.md` or `cerebrum.md` instead.
- **OpenSpec CLI v1.6.0 quirk:** `openspec validate` takes the change name **positionally** (`openspec validate <name> --strict`). There is no `--change` flag on validate, even though `status` and `instructions` do use `--change`.
- **The `CategoryClassifier` keyword table must be keyed on *normalized* strings, not natural spellings.** `classify()` normalizes the input first, and normalization folds a trailing plural — so "asparagus" arrives as "asparagu" and a table key of `"asparagus"` never matches (exact, word, and substring stages all fail). Same trap for chips/crackers/pretzels/nuts, hummus, couscous, molasses, brussels sprouts. Run every table key through `GroceryItem.normalize` at construction rather than hand-writing folded keys. `tasks.md` 4.1 does not say this.
- **The classifier's word-match stage has no documented tie-break for matches of *different* lengths**, and it decides most real multi-word groceries: "apple juice" (Produce vs Beverages), "potato chips" (Produce vs Snacks), "tomato soup", "chocolate milk", "chicken broth". The spec's only tie-break covers *equal*-length keywords. Applying it as written (earliest category order) sends all of the above to Produce. Needs a decision before 4.2 is written — English head-noun is the last word, so "prefer the last matching word" is the likely fix.

- **Model XML: Manual/None codegen is expressed by OMITTING `codeGenerationType`.** Writing `codeGenerationType="manual"` by hand makes momc fail the build ("unexpected code generation type 'manual'"). Only "class" and "category" are valid values.
- **`SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES` is set project-wide:** every file must directly import the module whose members it touches (e.g. `import CoreData` for `container.viewContext`), even if a type from that module arrives via another file.
- **`nonisolated` on type declarations works here** and is the right tool for Core Data model types under `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`: `GroceryItem`, `Household`, `ItemLocation`, `GroceryCategory`, and `CategoryClassifier` are all `nonisolated` so Core Data's background machinery and pure logic never touch the main actor. `GroceryStore` and the UI stay default-MainActor.
- **Headless verification pattern (no test target needed):** compile the pure-logic files plus a `main.swift` harness with plain `swiftc` on macOS, and compile the model separately with `xcrun momc <src>.xcdatamodeld <dst>.momd` then load it via `NSManagedObjectModel(contentsOf:)` + `NSInMemoryStoreType`. This exercised all GroceryStore/classifier spec scenarios (52 assertions) without Xcode. Harness lives in the session scratchpad; rebuild it when logic changes.
- **Simulator runs fine with zero signing setup** (`0 valid identities`, no team): entitlements are ad-hoc signed. What actually requires the user in Xcode: signing into the developer account, picking the team (sets `DEVELOPMENT_TEAM`), which auto-registers the App ID + CloudKit container on first signed build. Until then `initializeCloudKitSchema()` cannot succeed.
- **Xcode 27 beta simulators are iOS 27**; deployment target 18.0 builds and runs on them without issue. Build with `-derivedDataPath build_output` to match the repo's existing (gitignored) layout.
- **`INFOPLIST_KEY_*` names are an allowlist (96 keys in CoreBuildSystem.xcspec), and unknown names are SILENTLY ignored.** Neither `UIBackgroundModes` nor `CKSharingSupported` is supported. For unsupported keys: partial `Info.plist` with just those keys + `INFOPLIST_FILE` set while `GENERATE_INFOPLIST_FILE = YES` stays on — the two merge. The partial plist inside the synchronized folder then needs a `PBXFileSystemSynchronizedBuildFileExceptionSet` (`membershipExceptions = (Info.plist)`) or the build fails with "Multiple commands produce Info.plist". Verify by dumping the BUILT app's Info.plist, not by trusting settings.
- **`nonisolated` on a class declaration does NOT cover members added in extensions** — extension members still get the project's MainActor default (bug-025: `GroceryItem.normalize` silently became MainActor). Annotate extension members (or the extension) `nonisolated` explicitly, and compile the Release/device configuration at least once before shipping — it surfaced warnings the Debug/simulator greps had missed.
- **Under approachable concurrency, `await`ing an imported ObjC async method runs its blocking prefix on the CALLER'S actor** (`nonisolated(nonsending)`, SE-0461). `NSPersistentCloudKitContainer.share(_:to:)` blocks its calling thread, so awaiting it from MainActor froze the whole UI and deadlocked (bug-023). For blocking Core Data/CloudKit container APIs: use the completion-handler variant inside `Task.detached` + `withCheckedThrowingContinuation`, never a bare `await` from the main actor.
- **`fetchShares(matching:)` reads the LOCAL share cache**, which lags server-side deletes until the next mirroring import (bug-024). UI share state must live in a session-long object that remembers deletes (`SharingController.shared` + `deletedShareRecordIDs`), not in a per-presentation `@StateObject`.
- **CloudKit share acceptance lands on the *scene* delegate in SwiftUI apps** (`windowScene(_:userDidAcceptCloudKitShareWith:)`), not the app delegate. The `UIApplicationDelegateAdaptor` app delegate must install the scene delegate class via `application(_:configurationForConnecting:options:)`; keep the app-level `userDidAcceptCloudKitShareWith` too as a fallback for pre-scene delivery.
- **A brand-new CloudKit container on a fresh membership can return CKError 15 'Server Rejected Request' until first-time provisioning completes** — even with a provably correct provisioning profile. Opening the container once in CloudKit Console (icloud.developer.apple.com) and/or waiting ~15–30 min resolves it (bug-022). The schema push succeeded 2026-07-22 from the user's physical iPhone; dev environment now holds the schema, and 3.4/3.5 are closed.
- **`initializeCloudKitSchema` requires an iCloud account on the device/simulator** — fails with CKAccountStatusNoAccount otherwise (error 134400). Signing in via Settings on the simulator is enough. Mirroring setup failure with no account is logged loudly but harmless: local stores work, exactly the designed degradation.
- **Team ID is P8L779MGGP** (set by Xcode in the pbxproj when the user picked the team, 2026-07-22).
- **`@Published`/`ObservableObject` need `import Combine` under MemberImportVisibility** — SwiftUI alone doesn't surface them (bug-015 recurrence).
- **Simulator iCloud sign-in state: screenshot Settings or read the app's CKAccountInfo log lines.** `defaults read MobileMeAccounts` no longer exists on iOS 26 sims even when signed in (bug-020 false-negative led to shutting down the user's signed-in sim).
- **The user's Apple Account has Advanced Data Protection on (`walrus=Enabled`)** — CloudKit on simulators sticks at `CKAccountStatusTemporarilyUnavailable` because trusted-device key provisioning can't complete. Simulator CloudKit work needs either their physical iPhone or a non-ADP test Apple ID (which group 12 needs anyway as the second account).
- **SUPPORTED_PLATFORMS includes macosx/xros, so avoid iOS-only SwiftUI APIs** (bug-018). Use `.navigation` not `.topBarLeading`; `.toolbarTitleDisplayMode(.inline)` not `.navigationBarTitleDisplayMode(.inline)`; wrap `.textInputAutocapitalization` in postfix `#if !os(macOS)`. Compile-check macOS cheaply with `-destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO`.

## Decision Log

- [2026-07-21] **Shopping list and home inventory share one `GroceryItem` model** with a `location` field (`.shoppingList` / `.atHome`), rather than two separate models. Chosen because duplicate detection and merge-on-check-off need to query across both in one place; two models would duplicate fields and normalization logic. User picked this "check off → moves to pantry" flow over fully-separate lists and over a confirm-sheet variant.
- [2026-07-21] **Categorization uses a static compiled-in keyword dictionary, explicitly NOT AI.** Hard user requirement. Matching order: exact normalized name → single word → longest contained keyword → `.other`; equal-length ties broken by fixed category order for determinism.
- [2026-07-21] **Undo is an explicit `CheckOffUndo` value snapshot, not `UndoManager`.** Check-off has two branches (flip location vs. merge N into an existing home row and delete the list row); reversing the merge correctly requires knowing the delta N came from that specific check-off. Also gives a visible affordance, which shake-to-undo does not. Permanent recovery after the banner expires is the separate "Move to Shopping List" feature.
- [2026-07-21] **Duplicate warning uses two affordances:** a live inline "You have N at home" note under the name field, plus a confirmation alert on save. The note alone is too easy to miss when typing fast; the alert costs one extra tap only in the duplicate case. Cancel returns to a still-populated sheet.
- [2026-07-21] **REVERSED: Core Data + `NSPersistentCloudKitContainer`, NOT SwiftData.** Originally chose SwiftData (in-SDK, `@Query` for free). Reversed the same day when the user added iOS-to-iOS sharing as a requirement: **SwiftData mirrors only the private CloudKit database**; `CKShare` against the shared scope requires `NSPersistentCloudKitContainer`. Apple's own guidance is Core Data for shared/public databases. Do not propose SwiftData for anything in this project that touches sharing.
- [2026-07-21] **Sharing unit is the `Household` (a root entity owning all items), not the list.** `CKShare` shares a record and the graph beneath it, so sharing the Household carries list + inventory together. Sharing only the list would leave an invited member comparing it against their own empty inventory — the duplicate warning would silently mislead the exact person invited to avoid duplicates.
- [2026-07-21] **Quantity conflicts are last-writer-wins, accepted as a known v1 limitation.** `NSPersistentCloudKitContainer` merges per-property, and `quantity += N` is a read-modify-write, so simultaneous check-offs lose an increment. Upgrade path if it bites: model quantity as a sum of immutable adjustment records (inserts never conflict). Not done in v1 — costs a second entity + compaction, fights the simplicity goal.
- [2026-07-21] **Undo verifies before reversing.** Re-fetch the home item and compare against the expected post-check-off quantity; if it differs (another member edited it), restore the shopping-list row but leave the home quantity alone and say so. Sharing turned this from a theoretical race into a likely one.
- [2026-07-21] **Store both `name` and derived `normalizedName`** on the record. Normalization (trim/collapse/lowercase/strip punctuation/fold trailing plural) is applied symmetrically to stored names and lookups, which makes an imperfect plural stemmer harmless. Only exact normalized equality counts as a duplicate — no fuzzy matching, so "onion" never collides with "green onion".
- [2026-07-21] **v1 excludes expiry dates, shelf-life estimates, and notifications** (user's call), plus recipes, barcode scanning, and units of measure. Sync and sharing were originally excluded but the user added them the same day.
- [2026-07-21] **Every item fetch scopes to an `activeHousehold` from day one**, even though only one household exists until sharing lands. On accepting an invitation a second `Household` arrives in the shared store while the personal one remains in the private store; any fetch written without that predicate would show both households' items merged. Retrofitting the predicate means revisiting every fetch and view — introducing it early makes joining a household a one-line change to what `activeHousehold` points at.
- [2026-07-21] **Sync is enabled before feature code is written, not after.** Once the membership was approved, the CloudKit-ready-but-off pattern was dropped: entitlement and container in group 1, `cloudKitContainerOptions` attached in group 3. Reason: CloudKit's model constraints (all attributes optional/defaulted, no unique constraints, all relationships inversed) are not verifiable by inspection — with mirroring on, a violation throws at store load on the commit that caused it; with mirroring off, it stays silent until the store operations and fetches have already been written against a model that must then change. Cost is bounded because schema iteration happens in the resettable development environment.
- [2026-07-21] **iCloud account as identity, no auth system.** No Sign in with Apple, no sign-up screen. Accepted permanent ceiling: no Android, no web, ever, without adding a real backend.
- [2026-07-22] **Classifier matching is rightmost-wins, not longest-wins.** Replaced the old three-stage order (exact → any word → longest substring), which left the common case undecided: "apple juice" and "potato chips" each match two keywords in different categories and nothing said which won. New rule: exact whole-name match → the keyword whose last character falls **latest** in the name, matched on **word boundaries only** → `.other`. Same end position breaks by length, then `sortOrder`. Rationale: English grocery names are modifier-then-head-noun, so the final noun is what the item is ("chocolate milk" is milk, "milk chocolate" is candy). Length-at-equal-end is what lets `ice cream` beat `cream` in "vanilla ice cream". Word-boundary matching is what makes one stage safe — it is why "**bar**becue sauce" can't hit `bar`, which the old word-before-substring ordering existed to prevent.
- [2026-07-22] **Duplicate warning fires on the merge path too.** When a name is already on the shopping list *and* at home, adding it again still warns. An existing list row does not tell the user what is sitting in the kitchen, which is the only fact the warning exists to deliver. A list-only match stays silent.
- [2026-07-22] **`rename` is a multi-row operation and lives in `GroceryStore`.** Renaming into a name already used in the same location would create the duplicate row the model forbids and every downstream merge path assumes away. Rename merges like `addItem` does; the pre-existing row survives with its display name, category, and manual flag.
- [2026-07-22] **Undo's re-fetch has three outcomes, not two:** quantity matches, quantity differs, or the item is **gone**. Gone is the likelier failure path since decrement-to-zero deletes the row. It takes the mismatch branch — restore the list row, recreate nothing, report "changed elsewhere". Never treat a nil fetch as quantity 0.
- [2026-07-22] **Undo banner stays scoped to `ShoppingListView` state.** Leaving the tab dismisses it; "Move to Shopping List" is the permanent recovery path. Deliberately not hoisted above the `TabView` — shared mutable state across both screens is too much machinery for a 5-second window that already has a permanent replacement.
- [2026-07-22] **Bundle ID is `com.yixinxiao.nomorewaste`; CloudKit container is `iCloud.com.yixinxiao.nomorewaste`.** User chose it over the gmail-handle variant; user will sign into Xcode themselves rather than provide a Team ID, so `DEVELOPMENT_TEAM` is intentionally unset in the pbxproj.
- [2026-07-22] **CloudKit dev-schema push is an env-var opt-in, not a playground:** run once with `PUSH_CK_SCHEMA=1` in the scheme environment (DEBUG-only code path in `PersistenceController.pushCloudKitDevelopmentSchema()`), which satisfies task 3.4's "explicit opt-in flag" more safely than a temporary call.
- [2026-07-22] **On add/rename merges, the editor's category pick is deliberately dropped** when the save merges into an existing row — the grocery-items spec says the surviving item keeps its display name, category, and manual flag; only quantity changes.
- [2026-07-28] **App renamed `nomorewaste` → `xwaste`** (folders, xcodeproj, target, scheme, `XWasteApp`, `XWaste.xcdatamodeld`, entitlements filename, display name, CLAUDE.md). **Three things deliberately keep the old name — do not "fix" them:** bundle ID `com.yixinxiao.nomorewaste` (ASC record + TestFlight), CloudKit container `iCloud.com.yixinxiao.nomorewaste` (permanent), and store filenames `NoMoreWaste.sqlite`/`NoMoreWaste-shared.sqlite` (pinned via explicit description URL in PersistenceController so existing installs keep their data; the renamed model would otherwise default to `XWaste.sqlite`). Verified: build green, installed app shows display name xwaste, bundle ID unchanged, store files still NoMoreWaste*.sqlite on an existing install.
- [2026-07-28] **Task 10.1 (same-account two-device sync verification) deferred by user decision** — no second device on their iCloud account. Everything else in the change is verified, including all cross-account sharing scenarios on TestFlight/production. If a same-account sync bug ever surfaces, this is the untested path: private-database mirroring device-to-device.
- [2026-07-22] **Second shared household is an explicit non-goal.** A user has their personal household plus at most one joined household. Accepting an invitation while already in a shared household is undefined in this change.
